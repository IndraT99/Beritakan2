## 2024-05-17 - Missing ARIA Labels on Navigation Toggles
**Learning:** Found a pattern where interactive header toggles (search, offcanvas menus, close buttons) rely exclusively on FontAwesome icons (e.g. `<i class="fa-solid fa-magnifying-glass"></i>`, `<i class="fa-solid fa-bars"></i>`) without accompanying text or `aria-label` attributes.
**Action:** When adding or reviewing layout toggles and interactive icons in Blade templates, always ensure an `aria-label` is applied to the interactive parent (`<button>` or `<a>`) to guarantee screen reader support. Using translation functions `{{ __('...') }}` for these labels helps maintain accessibility across localizations. If there is a wrapped `<a>` that only contains an icon inside a `<button>`, also apply `aria-hidden="true"` to prevent duplicate/empty focus stops.
