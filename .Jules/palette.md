## 2024-05-18 - Nested Interactive Elements & Duplicate IDs on Responsive Toggles
**Learning:** When addressing accessibility for icon-only toggles (like search icons), we found multiple `<button>` tags with the same `id` (`dropdownMenuButton1`) for mobile and desktop views, which also contained nested `<a>` tags. Screen readers struggle with duplicate IDs and nested interactive elements (a link inside a button).
**Action:** When fixing accessibility for icon-only toggles in Blade templates where an `<a>` tag is nested inside a `<button>`, completely remove the redundant `<a>` tag leaving the icon (e.g., `<i>`) directly inside the `<button>` to prevent duplicate focus stops, ensure the parent `<button>` has an appropriate `aria-label`, and verify `id` attributes are unique across responsive viewports.
